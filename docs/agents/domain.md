# Domain docs

This repo uses a single-context layout:

- GLOSSARY.md at the repo root
- Architecture decision records under docs/adr/

Before exploring the codebase, read the glossary and ADRs relevant
to the work.

If these files do not exist, proceed silently. The domain-modeling
skill creates them as terms and decisions are resolved.

Use the glossary's vocabulary in issues, proposals, code, and tests.
Reconsider unfamiliar terms or note real gaps for domain-modeling.

Explicitly surface proposals that conflict with an existing ADR,
identifying the decision and why it should be reconsidered.
